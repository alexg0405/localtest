# Scoring rubric: RedNote second round

Score each area 1–5, or "not observed" when there is no evidence. This is a
no-AI round, and mostly behavioral: the stories matter as much as the code.

| Area | 1 | 3 | 5 |
|---|---|---|---|
| Problem understanding | Codes immediately. | Asks about repeated days or ordering. | Clarifies repeated days, ordering, empty input, what counts as consecutive, and input size. |
| Technical depth (résumé) | Describes the project only at a high level. | Explains how their part works and one decision. | How it works end to end, a decision with the rejected alternative, a real bug and how they found it, and what breaks at scale. |
| Behavioral questions | Vague, "we", no result. | STAR with some specifics. | Specific, personal actions, a measurable result, reflection, and strong follow-up answers, with a different story for each question. |
| Problem solving and complexity | No approach stated. | A working approach and its time complexity. | The sort-based and set-based approaches with their tradeoff, and a sliding window for the follow-up. |
| Correctness and edge cases | Example fails. | Example and most edge cases pass. | All edge cases, the follow-up, and performance. |
| Testing and dry run | No walkthrough. | Walks through the example. | Walks through edge cases and names the tests they'd write. |
| Code quality | Hard to follow. | Clear. | Short, well-named, no duplicated run-counting between the two functions. |
| Communication | Silent coding. | Explains when asked. | Narrates continuously, checks in with the interviewer, and asks good questions at the end. |
